## 2 · 复制指令出口（你拍板松绑的那条）

**形状**：不给整条目一个笼统的「卸下」按钮，而是**每条链接落点的行尾**给一个「复制卸下指令」。
理由就是你追问出来的那件事——卸下的作用域是"某一家 / 某一项目上的那一次挂载"，
一个笼统按钮会让人以为点一下哪都看不见了。

**三种情形说三种话**（不给假把手）：
- symlink 落点 + 真 Agent + Skill → 给指令；
- 实体源 / 实体副本（本体）→ **不给**。`unmount` 遇到本体会拒绝（"卸下会使其脱离全集"），
  给一个必然失败的指令就是骗人。走「删除」，全部落点进回收站；
- MCP 配置项 → **不给**。写侧是 story-6，没开。
- 目录名归属（`cli（目录名）`这种）→ **不给**。它不是可引用的产品，CLI 认不出。

真机验过"该给的给、不该给的不给"：`lark-mail` 八条落点里只有 3 条 symlink 出行尾指令，
实体源/实体副本/伪归属五行都没有；`access`、`docx` 全是实体落点，整页无指令，
动作区改说"这个条目没有可卸下的链接落点…要整体移除用「删除」"。

**复制到的内容**（`pbpaste` 实测）：`skillctl unmount lark-mail --on claude`，
与磁盘事实一致（`~/.claude/skills/lark-mail -> ../../.agents/skills/lark-mail`）；
CLI 接受这个参数形状（拿不存在的条目试，报的是"该位置没有挂载：~/.claude/skills/…"，
说明 agent 解析对了，不是语法错）。

**说明文案必须带的两句**：只摘那一处、源不动；**正在跑的会话要重启才看不见它**
（Codex 自动检测但不保证、Claude Code 会话启动时读、Cursor 重启会话/窗口）。
这句是从 `docs/agent-recon.md` 的"写回生效条件"来的，不写就等于承诺了做不到的即时性。

顺带清掉了那句过时文案「挂/卸将随 skillctl CLI 写侧启用」和永久禁用的「卸下」按钮
——CLI Phase 2 就交付了，那句话现在是假话（P3 攒的那条一并结掉）。

## 3 · 项目级 `--project`：验通了，但它先抓出一个真错

第一版指令里的 `--project` 取的是**索引里那个项目的 path**，而索引里的项目是按 `.git` 祖先
认出来的**仓库根**。真机一试就露馅：`skill-a` 的落点在
`client-a/knowledge-base/.claude/skills/skill-a`，可仓库根是 `client-a`——
复制出来的是 `--project ~/client-a`，而 CLI 的解析规则是
`<project>/<agentDir>/skills/<name>`，于是它会去找 `client-a/.claude/skills/skill-a`（不存在），
**在评委面前当场报"该位置没有挂载"**。

改成从**落点路径自己反推**（去掉 `<name>/skills/<agentDir>` 三段），形状对不上就宁可不给指令。
复验：`pbpaste` 得到 `skillctl unmount skill-a --on claude --project ~/client-a/knowledge-base`；
拿不存在的条目跑同一条指令，CLI 回的是
`该位置没有挂载：~/client-a/knowledge-base/.claude/skills/p2-nope`
——解析出的目录与真实落点同一层，说明路径对了。

顺带修掉一个 tooltip 遮蔽：行尾按钮本来带的是"指令 + 作用域 + 重启会话"那句提示，
但外层 HStack 的 `.help(spot.path)` 把它盖掉了，鼠标悬停只看到路径。现在路径挂在
路径文本上，按钮自己的提示才露得出来。

## 3b · 演示前要知道的一条

`--project` 只对**项目级落点**出现；用户级落点是 `skillctl unmount <name> --on <agent>`，
它一次摘掉那家名下**所有**候选目录里的落点（D19 的口径），不是只摘你看到的那一行。
讲的时候别说成"摘这一处"。
